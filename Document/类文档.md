该框架在VTK处理模型和图形系统的基础上，通过View类封装了VTK图形系统相关类对象，用于可视化流场。Representation类封装了第三章和第四章提到的算法，并封装了VTK处理模型的管线连接过程，简化管线连接过程。并为每一个表征类配置一个参数配置界面，用于流场可视化算法参数设置。

图 5-4给出View、Representation、ConfigWidget的类图。

![img](F:\VR_Code\iGreakWorks\iGreakWorks618\FlowViz\Document\类文档.assets\wps2-1747634901583.png)

图 5-4 View+Representation+Widget类图

一个View管理**多个Representation**，View可以添加和删除Representation。而每个Representation对应一个ConfigWidget，通过ConfigWidget可以修改Represetntation参数。 

View派生自vtkObject类，其核心功能是管理Representation类，包括了添加表征、删除表征、渲染表征等功能。内部维护一个Representation数组，通过addRepresentation函数可以添加指定Repesentation，并连接VTK管线。View封装了VTK可视化管中的vtkRender和vtkRenderWindow两个类，同时提供了视图控制相关函数，提供视角控制、相机缩放、旋转等功能。

Representation派生自vtkAlgorithm类，可直接接入到VTK的管线中。其封装了VTK管线中的vtkActor、vtkMapper、vtkProperty、vtkAlgorithm的指针。其中vtkActor和vtkMapper是一一对应的管线，vtkProperty用于设置场景中模型属性。而vtkAlgorithm指针在Representation子类进行创建，根据子类功能不同创建不同的算法对象。Representation的子类基于VTK实现具体的流场可视化算法。如IsoSurfaceRep类实现3.4中的等值面提取算法，StreamLineRep实现3.5中的流线生成算法、ParticleTraceRep类实现第四章提到的流线粒子追踪算法。顶层Representation类提供addToView函数，可以将自身添加到指定视图中。因此当需要添加新的流场可视化形式时只需要派生新类即可，保证了系统扩展性。图 5-5展示流场可视化系统不同可视化方法示意图。

ConfigWidget类派生自QWidget类，用于配置流场可视化算法参数，如切面云图的切面位置、提取等值面的等值、流线的种子位置，流面的种子位置、流线粒子追踪算法的积分步长等参数。ConfigWidget类包含Representatioin指针，通过setRepresentation()函数可以为当前类设置表征。对于不同的Representation类编写一个ConfigWidget子类，该ConfigWidget子类回调用对应的Representation类进行参数设置。如等值面表征类IsoSurfaceRep对应IsoSurfaceWidget，通过IsoSurfaceWidget可设置需要提取的等值。

## 工具栏类

工具栏负责交互控制，如何管理多个不同**按钮（QButton）**的**点击信号（clicked）**或**动作（QAction）**的**触发信号（triggered）**与**槽函数（slot）**进行连接，并复用这些槽函数对于可交互软件来说很重要。

比如我有两个界面相关类中每个类都有一个按钮，但这两个按钮功能一样，这种现象比较常见，比如你的工具栏的功能，你的菜单栏也有同样的功能。如果只是简单的connect，那么需要写许多重复代码（主要是**connect函数**的长度，与**回调槽函数**）。如下

```cpp
class A // 工具栏类
{
    A()// 构造函数
    {
        connect(btn1, clicked, this, onBtn1Clicked);
    }
	QPushButton* btn1; // 打开文件
    Q_SLOTS:
    void onBtn1Clicked();// 打开文件逻辑
    
}
class B //下拉菜单类
{
    B()// 构造函数
    {
        connect(btn2, clicked, this, onBtn2Clicked);
    }
    QPushButton* btn2; // 打开文件
    Q_SLOTS:
    void onBtn2Clicked();// 打开文件逻辑
}
```

但是其实你会发现，`onBtn1Clicked()`和`onBtn2Clicked()`的逻辑完全相同，就出现了代码冗余。同时往往connect函数的长度也足够长，并不好写。因此需要想办法**去对槽函数代码进行复用，并提供一种更简单的信号与槽连接方式**。

<img src=".\类文档.assets\image-20250514152714665.png" alt="wps2"/>

```c++
QObject::connect(&btn1, &QPushButton::clicked, this, &ClassName::onBtn1Clicked);
QObject::connect(&btn2, &QPushButton::clicked, this, &ClassName::onBtn2Clicked);
QObject::connect(&btn3, &QPushButton::clicked, this, &ClassName::onBtn3Clicked);
```

### Reaction模式

ParaView根据实现了一种**Reaction模式**，设计顶层**igwReaction类**对connect语句进行复用

<img src=".\类文档.assets\image-20250514160247015.png" alt="image-20250514160247015" style="zoom:67%;" />

<img src=".\类文档.assets\wps1-1747209138545.png" alt="wps1-1747209138545.png" style="zoom:80%;" />

**顶层的Reaciton类的构造函数负责，连接QAction的triggered信号以及自己编写的onTriggered虚函数。**

```cpp
class igwReacton : public QObject
{
	Q_OBJECT
public:
    igwReaction(QAction* actioin)
    	:QObject(action)
    {
      QObject::connect(action, SIGNAL(triggered(bool)), this,SLOT(onTriggered(bool)), type);
    }
    virtual void onTriggered(){};
}
```



![image-20250514155426236](.\类文档.assets\image-20250514155426236.png)

从**顶层Reaction类**的派生不同的**实现类**，都需要重写**onTriggered函数**，用于处理具体事件

当调用Reaction的子类**构造函数时**会自动调用**父类（顶层Reaction类）构造函数**，将传入的动作**（QAction）的触发信号（triggered）**与子类实现的**onTriggered**函数连接。**这样实现了信号与槽连接代码的复用**

此时的信号与槽连接代码变成了

```cpp
QAction* action1;// 动作1，也可以是按钮，不过我的代码里没有实现按钮相关的Reaction模式
QAction* action2;// 动作2
new igwAction1Reaction(action1);
new igwAction2Reaction(action2);
```

但是这样做也有一个问题，就是当你的**按钮和动作**非常多的时候你要写很多的**Reaction子类**，这样其实也并不是很好维护。因此，Reaction模式对近似功能的**按钮和动作**进行分类组合如下，**Reaction子类**根据分类的类别进行编写。

<img src=".\类文档.assets\image-20250514162850164.png" alt="image-20250514162850164" style="zoom:80%;" />

如为视图控制相关的按钮编写**igwCameraReaction子类**，然后在类中增加一个枚举类型**Mode**，用于区分按钮功能，在通过**构造函数进行连接**时传入**具体Mode**对当前**按钮类型进行区分**。且该类为每个**Mode**编写对应的**槽函数**，并在**onTriggered函数**中通过**switch**语句进行分发。

```cpp
class igwReacton : public QObject // 基类
{
	Q_OBJECT
public:
    igwReaction(QAction* actioin)
    	:QObject(action)
    {
      QObject::connect(action, SIGNAL(triggered(bool)), this,SLOT(onTriggered(bool)), type);
    }
    virtual void onTriggered(){};
}

class igwCameraReaction : public igwReaction
{
    enum class Mode
    {
        RESET_POSITIVE_X,// （看向X轴正方向）
        RESET_POSITIVE_Y,// （看向Y轴正方向）
        RESET_POSITIVE_Z // （看向Z轴正方向）
        ...
    };
    igwCameraReaction(QAcion* action, Mode mode)
    	:igwReaction(action)
        , ReactionMode(mode)
    {
        
    }

    void onTriggered()
    {
        switch(ReactionMode)
        {
            case Mode::RESET_POSITIVE_X:
        		this->ResetPositiveX();
        		break;

    		case Mode::RESET_POSITIVE_Y:
        		this->ResetPositiveY();
        		break;

    		case Mode::RESET_POSITIVE_Z:
        		this->ResetPositiveZ();
        		break;
                ...
        }
    }
    //槽函数
slots:
    static void ResetPositiveX(); // static 的目的是保证这个类也可以当工具类用
    static void ResetPositiveY();
    static void ResetPositiveZ();
private:
    Mode ReactionMode;// 成员变量
    
    
}
class igwFileReaction : public igwReaction
{
    enum class Mode
    {
        OPEN_FILE,// （打开文件）
        WRITE_FILE,// （写入文件）
       
        ...
    };
    igwFileReaction(QAcion* action, Mode mode)
    	:igwReaction(action)
        , ReactionMode(mode)
    {
        
    }

    void onTriggered()
    {
        switch(ReactionMode)
        {
            case Mode::OPEN_FILE:
        		this->OpenFile();
        		break;

    		case Mode::WRITE_FILE:
        		this->WriteFile();
        		break;
                ...
        }
    }
    //槽函数
slots:
    static void OpenFile(); // static 的目的是保证这个类也可以当工具类用
    static void WriteFile();// 忽略文件名参数的问题，只是做个示示例，打开文件并不一定适合这种方式
private:
    Mode ReactionMode;// 成员变量
    
    
}

// 具体使用场景中
// 相机控制相关
QAction* Action1;// 看向X轴正方向
QAction* Action2;// 看向Y轴正方向
QAction* Action3;// 看向Z轴正方向
...			
// 连接   
new igwCameraReaction(Action1, igwCameraReaction::Mode::RESET_POSITIVE_X);
new igwCameraReaction(Action2, igwCameraReaction::Mode::RESET_POSITIVE_Y);
new igwCameraReaction(Action3, igwCameraReaction::Mode::RESET_POSITIVE_Z);
// 文件操作相关
QAction* OpenFileAction;// 打开文件
QAction* WriteFileAction;// 写入文件

new igwFileReaction(OpenFileAction, igwFileReaction::Mode::OPEN_FILE);
new igwFileReaction(WriteFileAction, igwFileReaction::Mode::WRITE_FILE);
```
